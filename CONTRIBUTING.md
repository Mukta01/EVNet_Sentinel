# Contributing to EVNet Sentinel

Welcome to the EVNet Sentinel project! To ensure our team is perfectly aligned and our work maintains the highest quality, all contributors (human and AI) must strictly adhere to the following ruleset.

## 1. Issue Management and Assignment
- **Issue Creation**: Issues shall be created *only* by recognized contributors of the project.
- **Assignment**: An assignee can self-assign an issue, or `@shard-c6` can approve and assign the issue.
- **Review Requirements**: All issues and PRs MUST be reviewed and approved by the core maintainers: `@shard-c6` and `@Mukta01`.

## 2. Branching Strategy
- **Branch Creation**: All work must be conducted on a separate, dedicated branch.
- **Naming Convention**: Branches must be named clearly, referencing the issue they address. 
  - *Example*: `feature/issue-42-add-login` or `bugfix/issue-12-fix-accordion`.
- **Never push directly to `main`**.

## 3. Pull Request Guidelines
- **Detailed Summary**: Every Pull Request MUST include a comprehensive summary.
  - State clearly which issue is being addressed.
  - Explain the root cause of the problem (if a bug).
  - Detail the exact solution and architectural decisions provided by the assignee.
- **Reviews**: PRs cannot be merged until they have received explicit approval from `@shard-c6` and `@Mukta01`.

## 4. Code Quality and Documentation
- Ensure all code added is well-documented.
- Any future paper summaries or architectural decisions will be placed in the `docs/` folder when instructed.
- All AI assistants (`Antigravity`) are strictly bound by these rules as configured in `.agents/AGENTS.md`.

By following these rules, we ensure EVNet Sentinel remains a detailed, highly aligned, and secure project.
